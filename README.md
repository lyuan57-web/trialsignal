# TrialSignal

Clinical-trial competitive intelligence and operational-risk decision support built from
public, auditable data.

**[Open the public interactive demo](https://lyuan57-web.github.io/trialsignal/)**

The hosted demo is a browser-ready snapshot of 862 public records generated by the same
pipeline and model used by the local application. The repository intentionally excludes
the 293 MB local SQLite warehouse and raw snapshots; they are reproducible with the
ingestion commands below.

## Product decision

Trial planning teams need to benchmark comparable protocols, understand competition for
patients, and identify operational risk before a study launches. TrialSignal converts
daily registry records into traceable sponsor entities, historical changes, comparable
trial cohorts, and leakage-aware benchmarks.

This is a portfolio-scale engineering and decision-science system. It is not a medical
device, treatment recommendation, causal model, or replacement for proprietary site and
patient data.

## Implemented system

- paginated ingestion from ClinicalTrials.gov API v2;
- typed parsing of trial, sponsor, condition, intervention, location, design, and enrollment data;
- traceable sponsor normalization and fuzzy resolution with an abstention policy;
- relational storage with immutable snapshots and SHA-256 change hashes;
- sixteen executable data-quality contracts and ingestion lineage;
- competitive-landscape queries and evidence-based comparable-trial retrieval;
- leakage-aware logistic risk benchmark with a chronological holdout;
- Kaplan-Meier duration benchmarks that preserve right-censored ongoing trials;
- FastAPI, interactive web surface, Docker configuration, and CI.

The current multi-indication development extraction is not the final portfolio cohort. Remaining
release gates are tracked in [the delivery roadmap](docs/roadmap.md).

## Setup

```bash
python3 -m venv .venv
.venv/bin/pip install -e '.[dev]'
```

Run the offline fixture and tests:

```bash
make demo
make test
```

Run the live pipeline and application:

```bash
make ingest
make quality
make train
make api
```

Open `http://127.0.0.1:8000` for the product surface and
`http://127.0.0.1:8000/docs` for the API contract.

Choose a condition and extraction size directly:

```bash
.venv/bin/python -m trialsignal.pipeline \
  --condition "multiple myeloma" \
  --max-studies 500 \
  --database data/trialsignal.db
```

## Development evidence

The current development build contains 11,509 distinct trials across thirteen condition
queries, 3,218 normalized sponsor entries, and 8,028 condition labels. All blocking data contracts
passed; two warning categories were surfaced for analyst review.

The chronological model holdout produced ROC-AUC 0.871 and average precision 0.835.
These are development results, not final production claims. See the
[model card](docs/model_card.md) for the cohort, feature policy, and limitations.

The machine-readable evidence behind these statements is generated with `make report` and
stored in [`reports/validation.json`](reports/validation.json).

## Architecture

The local implementation deliberately uses SQLite so a reviewer can reproduce it without
credentials. Raw snapshots and domain contracts are kept independent of the future warehouse
adapter. A production deployment can move the same modeled entities to PostgreSQL after the
public data contract is stable.
